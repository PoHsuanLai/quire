# 11 BEHAVIOUR: Scrolling

Status legend: **settled** = decided with the user (plan, 2026-09-23); **proposed** = chosen
here, tune in the gallery, the user may override. Confidence of the basis: **H** primary source
or code, **M** reliable secondary source or imitation code, **L** observed or inferred,
**UNKNOWN** nothing published. "Plan" = `~/.claude/plans/vast-toasting-peach.md`; "B" and "C-B"
= its Appendix B and Appendix C section B. "Python daemon" = the running service
`~/.local/lib/magic-mouse-kde/magic_mouse_gestures.py` (v0.3.0-kde).

## 11.1 What this governs

Every scroll in every surface and app rendered by `shell-host` (Blitz documents): which node
scrolls (latching), the phases, tracking, momentum, rubber band, axis lock, conversion from
device units to pixels, keyboard scrolling, wheel mice, touchpads, the overlay scrollbar,
natural scrolling and double-scroll suppression. Device decoding and gesture recognition are
`12-BEHAVIOUR-gestures.md`; this document consumes its scroll stream. Foreign (non-Blitz)
clients scroll with their own toolkit physics; for them we only shape the input (§11.3.14,
12 §12.3.9).

## 11.3 Our behaviour (specification)

### 11.3.1 Ownership (settled)

`shell-host` owns scroll physics for every Blitz document (plan B "Ownership decision"):

1. The host does not forward wheel/axis input to Blitz's default scroll action. It runs its
   own engine (this document), writes **raw** offsets (`set_viewport_scroll` for the root,
   `get_node_mut(id).scroll_offset_mut()` for elements) every frame, requests its own frames,
   and sends its own scroll notification to Dioxus.
2. Exception: an element marked `data-wheel="capture"` (sliders, zoomable canvases; ds
   components only) receives the raw `BlitzWheelEvent` through `handle_ui_event`; its handler
   must `prevent_default` (Blitz then does not scroll); the engine does nothing for that
   gesture.
3. Every ds scroll container carries `scrollbar-width: none` (ds reset); the host paints the
   Mac-style thumb (§11.3.12).
4. `scroll-behavior: smooth` is banned by `ds::lint` (Blitz's 300 ms `ScrollTo` would fight
   the engine); programmatic scrolls go through `ScrollCmd` (§11.3.11).

### 11.3.2 Sources and normalisation

All sources become one of three engine inputs: **Gesture** (phased pixel deltas), **Step**
(a discrete jump animated smoothly) or **Command**.

| Source | Arrives as | Engine input | Momentum | Rubber band | Status |
| --- | --- | --- | --- | --- | --- |
| Magic Mouse on our surface | `palmrest` socket `Scroll{phase, dx_px, dy_px, t}` (12 §12.3.10), already axis-locked and accelerated | Gesture | yes (host) | yes | settled (plan B) |
| Touchpad / virtual touchpad on our surface | `wl_pointer` axis, `axis_source finger`, continuous px, `axis_stop` | Gesture: first axis event = Began, `axis_stop` on both axes = Ended | yes (host) | yes | settled (plan B) |
| Continuous non-finger (trackpoint) | axis, source `continuous` | Gesture, no momentum | no | no | proposed |
| Wheel mouse | axis, source `wheel`, `axis_value120` | Step, 120 = 1 detent = 60 px | no | no | proposed |
| Wheel tilt | source `wheel_tilt` | Step horizontal | no | no | proposed |
| Keyboard | key events (not in an editable) | Step or HeldKey | no | no | settled values (R18) |
| Programmatic | `ScrollCmd::{To, By, IntoView}` | Step (smooth) or immediate | no | no | proposed |

Compositor-delivered axis values already carry the compositor's natural-scrolling choice
(`wl_pointer.axis_relative_direction`); the host uses them as delivered. `palmrest` events are
in **finger direction**; the host applies `scroll.natural` to them (§11.3.13).

### 11.3.3 Latching (target chosen at gesture start)

At **Began** (after the axis is known, §11.3.9) the host picks the target once, from the node
under the pointer outwards, and keeps it for the whole gesture **and** its momentum and rebound:

1. The innermost scroll container on the locked axis that can move in the initial direction
   (not at its edge in that direction) is latched.
2. If none can move, the innermost **elastic** container (§11.3.7) on that axis is latched and
   rubber-bands.
3. If none is elastic, nothing is latched; the gesture is consumed with no effect.

Mid-gesture there is **no chaining**: a latched inner list that reaches its edge rubber-bands;
the outer page never moves in that gesture. Status: proposed (M: WebKit / AppKit latching; R2
H for "view under the pointer at flick start"). A new Began (fingers touch again) re-latches.
Pointer motion during momentum does not change the target (R2).

### 11.3.4 Phases

Engine phases mirror R1 (H):

| Phase | Gesture source | Engine |
| --- | --- | --- |
| MayBegin | palmrest: fingers down before the axis lock | stops running momentum and rebound instantly (touch-to-stop) |
| Began | palmrest: axis locked (first delta dropped, see 12); touchpad: first axis event | latch |
| Changed | every non-zero delta | tracking, 1:1 |
| Ended | palmrest: all fingers lifted or contact set changed; touchpad: `axis_stop` | momentum or rebound |
| Cancelled | palmrest: physical click or palm (12) | rebound only, velocity 0 |
| MomentumBegan / Changed / Ended | engine-generated | notifications only |

### 11.3.5 Tracking

While fingers are down the latched offset moves by exactly the delta (natural sign applied):
`offset += delta` with no smoothing (1:1; same no-easing rule as the dock, 10 §10.3.3). Frames are
requested only when an offset changed since the last frame. Velocity samples
`(t_device_or_arrival, cumulative_px)` are kept for the last 100 ms.

### 11.3.6 Momentum

| Value | Number | Status | Basis |
| --- | --- | --- | --- |
| Model | Mac Mouse Fix drag `v' = -a v^b` | proposed, tune in gallery | R4 (M); macOS R3 UNKNOWN |
| `a` | 30 | proposed | R4 |
| `b` | 0.7 | proposed | R4 |
| Stop speed | 1 px/s | proposed | R4 |

| Cap | `|v0| <= 12 000 px/s` | proposed (Chromium max ~20 946, R6) |

Worked numbers (§11.5.1): 2000 px/s -> 501.5 px in 0.976 s; 1000 px/s -> 203.7 px in
0.772 s; 5000 px/s -> 1650 px in 1.319 s; 12 000 px/s -> 5151 px in 1.749 s. For comparison

### 11.3.7 Rubber band

| Value | Number | Status | Basis |
| --- | --- | --- | --- |
| Applies to | ds scroll containers and the document viewport only; never the dock, menus, popovers, lists inside menus, the launcher result list, or text fields | settled (R14) |
| Elastic axis | an axis is elastic iff the node scrolls on it and (content > viewport on it, or it is the vertical axis of the document viewport) | proposed (M, AppKit "automatic" elasticity) |
| Stretch while fingers are down | iOS bounded formula `s = (1 - 1/(O c/d + 1)) d`, `c = 0.55`, `d` = viewport extent on that axis, `O` = accumulated overscroll in px | proposed, tune in gallery (R12 M; macOS R10 UNKNOWN) |
| Alternative (config) | Chromium linear `s = O / 20` | R11 (H as code) |
| Minimum before stretching | 10 px, only when the gesture began at the edge | proposed (R11) |
| Reversibility | moving back reduces `O`; `s = f(O)`; `O < 0` resumes normal scrolling in the same gesture | proposed |
| Snap-back | Chromium exponential: `s(t) = (s0 + v0 0.31 t) e^(-12.5 t)` (stiffness 20, amplitude 0.31, period 1.6) | proposed (R11) |
| End of rebound | when `|s| < 1 px` and `t >= 24 ms`: set `s = 0` exactly, emit MomentumEnded | proposed (R11) |
| Momentum impact | Rebound with `s0 = 0`, `v0` = impact velocity (outward positive) | proposed (R11) |
| Wheel, keyboard, programmatic | never stretch; clamp | proposed |
| Raw offset | written offset = edge offset + sign x s (out of range, painted by Blitz with the container background showing) | settled (plan B) |

Worked numbers (`d = 1000`): O = 100 -> s = 52.1 px; O = 300 -> 141.6 px; O = 1000 -> 354.8 px.
Linear alternative: O = 1000 -> 50 px. Snap-back from 100 px, `v0 = 0`: `|s| < 1` at 368 ms.
Impact at 2000 px/s: peak 18.3 px at 80 ms, below 1 px at ~451 ms.

**`data-overscroll="band"`, by container.** "Applies to" above is the rule; this is the rule
applied to every scroll container quire or a consumer draws, so the host can read one attribute
rather than re-derive "is this a menu" from a class name. A container the host finds without the
attribute clamps (no rubber band) rather than defaulting to elastic — the safer failure, since an
un-marked scroller is more likely a mistake than a menu quire forgot to exclude.

| Container | `data-overscroll` | Why |
| --- | --- | --- |
| `Panel` (`.ds-panel`, the notification center's edge panel) | `band` | an ordinary ds scroll container, not on the exclusion list |
| `Sheet` (`.ds-sheet`, the general modal panel for settings and dialogs) | `band` | same: a panel, not a menu or a popover |
| A list's row scroller (mailo's `.list`, design/01-LAYOUT.md section 5; not a ds component — the consumer's own scrolling wrapper around `AnimatedList`) | `band` | ordinary list scrolling |
| The reader (mailo's `.reader-body`, design/01-LAYOUT.md section 7, drawn as `Peek`'s or `Sheet`'s `children`) | `band` | ordinary document scrolling; `Peek`'s own `.ds-peek` is `overflow:hidden` and never scrolls itself |
| `Menu` (`.ds-menu`) | absent | excluded by name (R14): a menu never rubber-bands |
| The dock | absent | excluded by name (R14) |
| `Popover` (`.ds-popover`), the launcher result list | absent | excluded by name (R14) |
| `TextInput` multiline (`.ds-input[*|data-kind=multiline]`) | absent | a text field (R14); it still carries `scrollbar-width:none` (item 1) since that is unconditional |

Every row above still carries `scrollbar-width: none` (item 1): the attribute governs only
whether the host lets the container stretch past its edge, not whether Blitz paints its own
scrollbar (that is banned everywhere a ds container scrolls).

### 11.3.8 Scroll acceleration (device units to px)

For the Magic Mouse the conversion is computed once, in `palmrest` (12 §12.3.8), so that our
surfaces and foreign clients get the same distance for the same stroke. It keeps the Python
daemon's feel as the starting point (settled):

| Value | Number | Status | Basis |
| --- | --- | --- | --- |
| Raw units per detent | `(64 - speed) x 7` = 294 at `speed = 22` | settled (Python `SCROLL_SPEED 22`, `SCROLL_ACCEL_BASE 7`) |
| Detent in px | 60 px | proposed (M: 3 lines x 20 px, the KDE default feel the daemon was tuned against; Blitz Lines x20) |
| Base gain | `60 / 294` = 0.2041 px per raw unit | derived |
| Velocity gain | `1 + min(rate / 2000, G_v - 1)`, `rate` = raw units/s of the sample, only if `0 < dt <= 50 ms`, `G_v = 2.0` | settled (Python) |
| Repeat gain | divisor `D` starts 7; each new contact set within 0.5 s of the last output: `D = max(1, D - 1)`, else `D = 7`; gain `min(G_r, 7/D)`, `G_r = 2.3` (sequence 1.0, 1.167, 1.4, 1.75, 2.3) | settled (Python) |
| Momentum | computed from the gained px, so it is "accelerated too" | proposed (R15) |
| Wheel detent | 60 px, no acceleration in v1 | proposed (R15 table UNKNOWN for our mice) |
| Touchpad | px as delivered by libinput through the compositor; no extra gain | proposed |

### 11.3.9 Axis lock (predominant axis)

| Source | Rule | Status |
| --- | --- | --- |
| Magic Mouse | the Python lock, executed in palmrest: accumulate centroid deltas; lock X when `|x| >= 40` and `|x| >= 1.5 |y|`, Y symmetrically; the accumulated pre-lock motion is **dropped** (no jump); unlock when a non-zero delta arrives `>= 0.25 s` after the previous motion; two fingers locking X become Blocked (they belong to the workspace swipe); all in raw units | settled (Python `SCROLL_LOCK_THRESHOLD 40`, `SCROLL_LOCK_RATIO 1.5`, `SCROLL_LOCK_TIMEOUT 0.25`) |
| Unlock in phase terms | palmrest emits Ended (no momentum: the finger was idle >= 0.25 s so `v0 = 0` by the held-still rule), then MayBegin, then Began at the re-lock; the host re-latches | proposed |
| Touchpad on our surface | accumulate until `max(|dx|,|dy|) >= 10 px`, lock the larger axis (ratio 1) for the gesture and its momentum; no free diagonal scrolling | proposed (R17 H, R11 ratio 1 and 10 px) |
| Wheel | per event: vertical unless the event is horizontal or Shift is held | proposed |

### 11.3.11 Wheel mice and programmatic scrolls

- Each detent adds `60 x value120/120` px to the pending **target** on the axis; the offset
  animates to the target with the keyboard smooth rule (1000 px/s, 200 ms cap, `--e-out`);
  detents arriving during the animation accumulate. Clamped at the edges; no momentum; no
  rubber band. (proposed; R18 H for the smooth rule)
- Latching for wheels: the target is chosen per detent burst: events less than 300 ms apart
  keep the previous target (proposed, avoids a list stealing the page scroll mid-burst).
- `ScrollCmd::To{node, offset, Animate::Smooth | Animate::Instant}`, `By`, `IntoView{rect,
  margin: 8}` use the same smooth rule.

### 11.3.13 Natural scrolling

Default **ON** (R16 H). One Settings value `scroll.natural`; the Settings app writes it to our
config (applied by the host to palmrest events) and to the compositor's per-device settings for
mice and touchpads including the palmrest virtual touchpad (COSMIC `com.system76.CosmicComp`
input config; KWin `kcminputrc`), so our surfaces and foreign clients agree. Status: settled
default, mechanism proposed.

### 11.3.14 Double-scroll suppression

The same finger stroke can reach one of our surfaces twice: directly from palmrest, and through
the compositor from the palmrest virtual touchpad (or from the kernel wheel emulation if it is
ever re-enabled). Wayland does not identify the device, so (settled rule, plan B, extended):

1. **Primary**: each host tells palmrest when the pointer is over one of its surfaces
   (`PointerOver{ours}` on `wl_pointer.enter`/`leave`, 12 §12.3.10); while any subscriber
   claims the pointer, palmrest sends nothing to the virtual touchpad or wheel device.
2. **Safety net**: the host drops `wl_pointer` axis events of source `finger` **and** `wheel`
   on its surfaces while palmrest reports fingers down, or momentum/rebound driven by palmrest
   is running, or for a 150 ms grace after the last palmrest Ended (or until an `axis_stop`
   arrives, whichever is first). A real wheel mouse used during that window is ignored.
3. Never set `emulate_scroll_wheel=0` without palmrest (or the Python daemon) running: it
   disables Magic Mouse scrolling everywhere (plan B).

### 11.3.15 Frames and notifications

- The engine requests frames only while Tracking with new deltas, Momentum, Rebound, Smooth,
  HeldKey, Spring, or while the thumb is fading/expanding. Idle = 0 frames.
- Each frame: `resolve(t)`, write raw offsets, paint, then emit
  `ScrollNotification{node, offset, phase}` on a `watch` channel; `ds_native::use_scroll(node)`
  exposes it to components. Blitz's own `onscroll` does not fire for raw writes (B).

## 11.4 State machine

Pure, `shell-host/src/scroll/engine.rs`. Geometry is passed in as values; the host reads it
from Blitz before calling `step` and applies effects after.

```rust
pub struct Px(pub f32);
pub enum Axis { X, Y }
pub enum Dir { Neg, Pos }
pub struct NodeRef(pub usize);                       // Blitz node id
pub struct Geom { offset: Px, max: Px, viewport: Px, elastic: Elastic }
pub enum Elastic { Elastic, Rigid }
pub struct Latch { node: NodeRef, axis: Axis }
pub struct Samples(/* ring of (Instant, Px) over the last 100 ms */);

pub enum Engine {
    Idle,
    Pending  { since: Instant },                               // MayBegin seen, axis unknown
    Tracking { latch: Latch, samples: Samples, over: Px /* O */, began_at_edge: AtEdge },
    Momentum { latch: Latch, v0: f32, t0: Instant, x0: Px },
    Rebound  { latch: Latch, s0: Px, v0: f32, t0: Instant },
    Smooth   { latch: Latch, from: Px, to: Px, t0: Instant, dur_ms: f32 },
    Held     { latch: Latch, key: KeyStep, t0: Instant, x0: Px },
    Spring   { latch: Latch, x0: Px, v0: f32, target: Px, t0: Instant },
}
pub enum AtEdge { AtEdge, Inside }

pub enum ScrollIn {
    Gesture { phase: Phase, delta: (Px, Px), t: Instant, source: GestureSource },
    Step    { axis: Axis, px: Px, node_hint: Option<NodeRef> },
    KeyDown(KeyStep), KeyUp(KeyStep),
    Cmd(ScrollCmd),
    Frame,
}
pub enum ScrollOut {
    SetOffset { node: NodeRef, axis: Axis, raw: Px },
    Notify    { node: NodeRef, phase: NotifyPhase },
    Thumb(ThumbOp), RequestFrames, StopFrames,
}

pub fn latch(chain: &[(NodeRef, Axis, Geom)], axis: Axis, dir: Dir) -> Option<Latch>;
pub fn step(e: Engine, input: ScrollIn, now: Instant, g: &Geom) -> (Engine, Vec<ScrollOut>);
```

| From | Input | To | Effects |
| --- | --- | --- | --- |
| any except Tracking | Gesture MayBegin | Pending | Momentum/Rebound/Smooth stop at the current offset; StopFrames if nothing else animates |
| Idle / Pending / Smooth | Gesture Began | Tracking (latch via `latch()`; none -> Idle) | Notify Began |
| Momentum with `|v| >= 350`, same dir | Gesture Began | Tracking, remember `v_boost` | |
| Tracking | Changed | Tracking | SetOffset (1:1 or stretched), RequestFrames |
| Tracking | Ended, `s = 0`, `|v0| >= 100` | Momentum | Notify MomentumBegan |
| Tracking | Ended, `s != 0` | Rebound{s0 = s, v0} | |
| Tracking | Ended, else / Cancelled with `s = 0` | Idle | Notify Ended |
| Tracking | Cancelled, `s != 0` | Rebound{v0 = 0} | |
| Momentum | Frame, `v(t) <= 1 px/s` | Idle | Notify MomentumEnded, StopFrames |
| Momentum | Frame, edge reached, elastic | Rebound{s0 = 0, v0 = v(t)} | |
| Momentum | Frame, edge reached, rigid | Idle | clamp, StopFrames |
| Rebound | Frame, `|s| < 1` and `t >= 24 ms` | Idle | SetOffset(edge), Notify MomentumEnded |
| Idle | Step / Cmd | Smooth (target accumulates if already Smooth) | |
| Smooth | Frame, `t >= dur` | Idle | |
| Idle / Smooth | KeyDown held (second repeat) | Held | |

Thumb machine (separate, same file): `Hidden -> Shown{last_change} -> Fading{since} -> Hidden`,
`Shown -> Expanded{hover}`; transitions on SetOffset, Frame (500 ms / 240 ms timers), pointer
proximity.

## 11.5 Formulas

Units: px, s, px/s. `t` = time since the phase started.

### 11.5.1 Momentum (Mac Mouse Fix drag)

```
v' = -a v^b                                    a = 30, b = 0.7
v(t) = (v0^(1-b) - (1-b) a t)^(1/(1-b))        = (v0^0.3 - 9 t)^(10/3)
x(t) = (v0^(2-b) - (v0^(1-b) - (1-b) a t)^((2-b)/(1-b))) / ((2-b) a)
     = (v0^1.3 - (v0^0.3 - 9 t)^(13/3)) / 39
t_stop = (v0^0.3 - v_stop^0.3) / 9             v_stop = 1 px/s
x_total = (v0^1.3 - 1) / 39
```

### 11.5.2 Release velocity

```
over samples (t_i, X_i) with t_i >= t_end - 80 ms, n >= 3:
v0 = sum((t_i - t_mean)(X_i - X_mean)) / sum((t_i - t_mean)^2)
if t_end - t_last > 50 ms: v0 = 0
v0 = clamp(v0 (+ v_boost), -12000, 12000)
```

Timestamps: palmrest device time when calibrated (12 §12.3.1), else arrival `CLOCK_MONOTONIC`.

### 11.5.3 Rubber band

```
stretch (bounded):   s(O) = (1 - 1 / (O c / d + 1)) d            c = 0.55, d = viewport px
inverse:             O(s) = s d / (c (d - s))                      (used when a gesture starts in overscroll)
stretch (linear):    s(O) = O / 20                                 config alternative
minimum:             O_eff = max(0, O - 10) if the gesture began at the edge
snap-back:           s(t) = (s0 + 0.31 v0 t) e^(-12.5 t)           12.5 = 20 / 1.6
end:                 |s| < 1 px and t >= 0.024 s  ->  s = 0
```

### 11.5.4 Smooth step and held key

```
smooth:  dur = min(|to - from| / 1000, 0.2) s ;  x(t) = from + (to - from) e_out(t / dur)
         e_out = cubic-bezier(.22, .9, .30, 1)
held:    v(t) = min(t / 0.2, 1) * 25 * step   px/s ;   x(t) = x0 + integral
spring:  x'' = -175 (x - target) - 20 x'      (m = 1); zeta = 20 / (2 sqrt 175) = 0.756, overshoot ~2.6 %
```

### 11.5.5 Magic Mouse units to px (computed in palmrest)

```
px = raw * (detent_px / ((64 - speed) * 7)) * g_repeat * g_velocity
detent_px = 60, speed = 22           -> 0.2041 px per raw unit at gain 1
g_velocity = 1 + min((|raw| / dt) / 2000, G_v - 1)  if 0 < dt <= 0.05 s else 1 ;  G_v = 2.0
g_repeat   = min(G_r, 7 / D) ; D in 1..=7 per 11.3.8 ;  G_r = 2.3
```

### 11.5.6 Scrollbar

```
L   = viewport - 2 * 2 (inset) [- 12 if the other axis track is visible]
len = max(18, L * viewport / content)
pos = (L - len) * offset / max_offset
overscroll: len' = max(18, len * (1 - |s| / viewport)), pinned to the overshot end
opacity(t) = 1 for t < 0.5 s after the last change; 1 - (t - 0.5)/0.24 until 0
```

| Settings UI | Settings app; writes both our keys and the compositor's natural-scroll keys |

Platform limits:

- Blitz raw setters do not clamp, redraw, emit scroll events or show scrollbars; the next
  clamped Blitz scroll snaps back (B). Therefore no Blitz scroll path may run: wheel events
  are not forwarded (except `data-wheel="capture"`), keyboard scroll keys are consumed by the
  host before Blitz, `scroll-behavior: smooth` is linted.
- Unverified: a public way to inject Blitz Scroll DomEvents (B); our notification channel
  replaces it.
- Foreign clients (GTK, Qt, Chromium, Firefox) do their own kinetic scrolling from the virtual
  touchpad's finger source + `axis_stop` (GTK needs `gdk_scroll_event_is_stop`); their curves
  differ from ours (R8, R9). Accepted.
- Magic Mouse on stock libinput has no `axis_stop` (R20); this is why palmrest exists.
- KWin and cosmic-comp both deliver `axis_source` and `axis_stop` (wl_pointer v5+); the
  suppression rule depends on it.

## 11.8 Acceptance tests

Pure tests drive `step` with synthetic streams at 120 Hz and `now` advanced by hand; host tests
use `debug-inject` + FrameStats in nested cosmic-comp.

1. **Flick model**: Changed deltas forming a steady 2000 px/s for 100 ms, then Ended:
   momentum travel 501.5 px +- 5 % (476..527), MomentumEnded at 976 ms +- 1 frame after Ended.
2. **Held still**: same stroke, then 60 ms with no delta, then Ended: no momentum.
3. **Boost**: second 2000 px/s flick begun while `v = 1000 px/s`, same direction: `v0 = 3000`
   +- 2 %; opposite direction: `v0 = -2000`.
4. **Touch to stop**: MayBegin during momentum: offset unchanged on the next two frames.
5. **Rubber band stretch**: at the top of a 1000 px viewport, a gesture that began inside pulls
   100 px past the edge: `s = 52.1 +- 1`; 1000 px: `354.8 +- 1`; with `Linear`: 5 and 50.
   Began at the edge: the first 10 px do not stretch.
6. **Snap-back**: release at `s = 100`, `v0 = 0`: offset back at the edge exactly (0 px error)
   at <= 400 ms; `s` monotonic; `|s| < 1` at 368 ms +- 1 frame.
7. **Impact**: momentum hits the edge at 2000 px/s: peak stretch 18.3 +- 1 px at 80 ms +- 1
   frame; settled <= 460 ms.
8. **No rubber band** on the dock, a ds `Menu`, the launcher list: 500 px of overscroll gives
   `s = 0` on every frame.
9. **Latching**: page with an inner list. (a) inner at its bottom, gesture down over it: the
   page scrolls, the inner never moves. (b) inner mid-way: the inner scrolls to its edge then
   stretches; the page offset is unchanged through the gesture and its momentum.
10. **Scrollbar**: visible on the first changed frame; opacity starts falling 500 ms +- 1 frame
    after the last change and is 0 at 740 ms +- 1 frame; thumb length at `s = 250` on a 1000 px
    viewport is 75 % of its in-range length (>= 18).
11. **Keyboard**: Down: +40 px, animation done in 40 ms +- 1 frame. PgDn on a 900 px viewport:
    +860 px in 200 ms +- 1 frame. End: at max in <= 200 ms. Held Down for 1 s: speed reaches
    1000 px/s at 0.2 s +- 1 frame; after KeyUp the offset follows `target - 100 e^(-10 t) cos(8.66 t)` within 1 px and settles within 0.5 px in <= 600 ms.
    Keys in a text input do not scroll.
12. **Wheel**: one detent: +60 px in 60 ms +- 1 frame; five detents within 50 ms: target +300,
    reached <= 250 ms after the first; no stretch at an edge.
13. **Double scroll**: palmrest stream plus the same stroke through the virtual touchpad over
    one of our surfaces: offsets equal the palmrest-only run within 1 px.
14. **Idle**: 5 s after the last settle: 0 frames, 0 commits.
15. **Natural**: with `Natural`, a finger moving toward the user (palmrest +y) decreases the
    vertical offset (content follows the finger); `Traditional` inverts; compositor-delivered
    touchpad events are not inverted twice.
16. **Python parity** (with 12 §12.8): a recorded hidraw capture replayed through palmrest's
    `feel` and through the Python `ScrollAxisLock`: cumulative px / (60/120) equals the Python
    cumulative v120 within 1 v120 unit on every report.

## 11.9 Open decisions

1. Momentum curve: Mac Mouse Fix (502 px for a 2000 px/s flick) vs iOS `r = .998` (~1000 px).
   macOS trackpads feel closer to the longer glide. Tune in the gallery.
2. Rubber band stretch: Bounded iOS (355 px at 1000 px of overscroll on a 1000 px view) vs
   Chromium Linear (50 px). Bounded proposed because Linear is very stiff under a finger.
3. Keep the Python repeat gain (up to 2.3x) now that momentum exists, or reduce it.
4. Wheel acceleration for ordinary mice (macOS accelerates; table UNKNOWN for our devices).
5. Detent = 60 px vs the Blitz / Chromium Linux ~53 px.
6. Whether keyboard scrolling should rubber-band at the ends (WebKit Mac does a small bounce).
